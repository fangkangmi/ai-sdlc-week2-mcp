1 · What MCP is · Transports

Must the server keep running?

Local · stdio

No

Copilot starts it when it needs the tools and stops it when it's done. It runs on your laptop and talks over stdin and stdout, like a plugin.

Remote · Streamable HTTP

Yes, like any web API

It runs on a server and Copilot calls a URL. With no sessions since 2026-07-28, any copy can answer, so it scales like a normal service.

Trap: run python server.py yourself and it looks frozen. It's waiting for a client to write to it.

Hand-roll an MCP server

The two standard transports. Same JSON messages either way; only the pipe differs. Local (stdio): the client launches the server as a child process and writes JSON lines to its stdin. When the client closes the pipe, the server exits. In our recorded runs the run script never started the server: Copilot did, and it ended with the run. The homework's talk() helper does the same thing by hand. Remote (Streamable HTTP): a web service at a URL, up like any API. The 2026-07-28 revision removed protocol sessions, so a request can land on any replica behind a load balancer; state like claim statuses lives in your data, not in the connection. In a bank, a remote MCP server is an internal service behind the usual authentication. The older HTTP+SSE transport is deprecated. "MCP means remote" is a common mix-up: our claims server never leaves the laptop.
