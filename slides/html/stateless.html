The 2026-07-28 revision of the spec removed the initialize handshake and protocol sessions. Every request now carries its protocol version and client capabilities in a _meta field; servers must answer server/discover so a client can check versions up front if it wants to. Why it matters: a remote MCP server can sit behind a load balancer like any web API, with no sticky sessions. Stateless protocol does not mean stateless application. If a server needs state across calls, it hands out an explicit ID (a claim, a job, a transaction) and the agent passes it back on the next call. The conversation itself still lives in the host: Copilot keeps adding tool results to the chat. If asked what's running today: the mcp Python SDK 2.2.0 speaks 2026-07-28, and its own client negotiates it automatically. The same server still answers the pre-2026 initialize handshake, which is what Codex 0.158 sends (its 2026-07-28 support is switched off). The Copilot CLI (1.0.89) sends 2026-07-28, recorded in runs/2026-09-30-copilot-*/wire.log. VS Code's own client wasn't checked; its output log shows it (MCP: List Servers, Show Output). "List the tools, then call one" holds either way. More in mcp-brief.md.
