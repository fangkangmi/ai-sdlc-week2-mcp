Tools, resources and prompts are the three core things a server can offer. Today's demo and the homework use tools only; one line each on the others is enough. Skills are an optional extension, io.modelcontextprotocol/skills (SEP-2640), marked Final on 13 Sep 2026. It sits on top of Resources: the server lists skills with skills/list, and the host reads SKILL.md and its files with resources/read. It is the same SKILL.md format as week 1's .github/skills, but served by the system it describes, so the instructions stay next to the service. The host verifies each file against a manifest of SHA-256 digests and must ask the user before running anything a skill brings. Be honest about adoption: the MCP site's support table (checked 29 Sep) doesn't list VS Code Copilot for Skills, and the Python SDK's support is still an open pull request. Say "coming", not "available". Skill content from a server is untrusted input, exactly like tool output in the second demo.
