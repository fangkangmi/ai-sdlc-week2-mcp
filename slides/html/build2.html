Same chat, about a minute each; skip this slide if you're late, it's Part 4 of the homework. One run is an anecdote. What the recorded runs did (GPT-6-Luna, one run each): asked "What's the status of claim CLM-1001?" with no hint, Codex searched the repo and never touched the claims tools; the Copilot CLI called get_claim straight away. Codex hides MCP tools behind a tool search by default; Copilot shows them to the model up front. From the Copilot runs: in all 4 triage runs it called lookup_policy at the same time as get_claim, before it knew the policy number. It guessed "CLM-1002", "", "", and once "HOM1234567": a real policy that belongs to a different customer, which it read. The error message, or the claim that came back, put it right each time. Design fix: return the policy with the claim, so there is nothing to guess. One mcp 2.x gotcha worth showing: raise ToolError for errors the model should read. Any other exception (a plain ValueError, say) counts as a crash, and the model sees only "Error executing tool get_claim": the message that would have taught it is thrown away. The checklist comes from Anthropic's "Writing tools for agents": a few tools shaped around the task beat one tool per API endpoint, and error messages should teach.
