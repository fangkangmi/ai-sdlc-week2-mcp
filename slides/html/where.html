How does Copilot find the tool?

01

You told it

.vscode/mcp.json holds a command for a local server, or a URL for a remote one.

02

It starts first

Copilot starts the server and asks for its tools before the model sees anything.

03

Names only

The model sees claims-get_claim, a description and inputs. The prefix routes the call.

Only tools in the config exist for the model. It can't go looking for others.

For a local server the "address" is a command line, not a URL. From the recorded Copilot CLI run on 30 Sep: at 15:45:11.1 Copilot read the config and started server.py ("pending"), at 11.6 the server answered ("connected"), and only at 13.0 did Copilot send the question and the tool list to the model. Copilot needs the tool list before the first model call, which is why it starts the server first. The model sees claims-get_claim: no path, no command, no process. When it replies "call claims-get_claim", Copilot reads the prefix (the server's name in mcp.json) and sends the call to that server. Codex does the same with a different format, mcp__claims__get_claim. For a remote server the config holds a URL instead of a command; everything else is the same. An analogy if it helps: phone contacts. You save the number once (the config); the assistant says "call the claims team" (the tool name); the phone dials.
